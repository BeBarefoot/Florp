# Enviz technical investigation and Florp roadmap

20 November 2026 · Follow-on to the [production POC plan](PRODUCTION_POC_PLAN.md) and [issue #1](https://github.com/BeBarefoot/Florp/issues/1).

Build a local, editable walkthrough first. Generate a usable draft from a supported plan in minutes, let the user fix or furnish it immediately, and run expensive visual generation only when requested. Measure the draft and the reviewed result separately. Enviz quotes 1–3 hours for a same-day home conversion starting at US$149. Its price includes the 3D build, share link and one revision, with additional AI credits sold separately. The right comparison is a reviewed, walkable model with similar scope and quality. [Enviz pricing](https://www.enviz.co/pricing)

**Observed in the public demo:** Chromium loaded a canvas, WebAssembly build assets and a Unity loader that initialized a Unity instance. This confirms Unity WebGL for that viewer. [Public example](https://app.enviz.co/?intent=view%2FIBEN)

The product behavior suggests a pipeline with reusable geometry, scene assets and view-dependent visual generation. Possible implementations include plan recognition followed by parametric reconstruction, and model edits that operate on object or geometry state. Enviz has not disclosed enough to identify its consumer parser, model vendors or weights, scene representation, prompt execution strategy, video method, level of human intervention, or time spent at each stage. The advertised turnaround is an order-to-delivery figure. The Pro pipeline and patent document specific technical approaches without establishing the consumer implementation.

## Florp architecture

Keep [the existing architecture](ARCHITECTURE.md): FastAPI, SQLite and local files for this release, PlanModel v2 and PlanRevision as authority for walls/openings/rooms, SceneRevision for objects and cameras, and Three.js for derived geometry. Keep [local ComfyUI](LOCAL_COMFY.md) as an optional image renderer on the M5 / 48 GB Mac. Ordinary walkthroughs, edits and material previews need zero cloud inference calls.

1. **Evidence to plan.** For supported vector PDFs, prototype extracting strokes, text, dimensions and sheet coordinates with the existing PDF dependency. Compare it to today's raster extractor on the same documents, carrying both into the same coordinate system and retaining raster fallback. Use OCR for labels or dimension candidates on scans, and optional local symbol detection for fixtures. Resolve geometry with deterministic snapping, wall hosting, room closure and scale checks. Preserve which page, crop and source supported each proposal. Ask the user to confirm scale and individually approve or dismiss fixtures. Flag contradictions and assumed elevations.
2. **Plan to walkthrough.** Reuse current meshes and GLB exporter. Add collision against actual wall/opening geometry, safe room spawn points, standing eye height, touch and keyboard controls, point-to-move and a dollhouse toggle. Fixed fixtures and furniture use a curated, licensed GLB catalog with metric footprints, anchors and material slots. Add, rotate, resize, replace, move and delete in 2D or 3D, with undo. Build navigation from portals/floor connectivity so a tour cannot walk through a closed wall. Measure actual mobile rendering before choosing asset compression or mesh/texture streaming.
3. **Prompt to edit.** Keep model editing and image generation as separate actions. Ship manual edit commands and a deterministic command parser for a few common edits first. Evaluate a local structured-output model on the Mac only if it materially improves language coverage. Pass selection IDs, type, size, relevant neighboring geometry and units. Return typed commands such as move object, replace finish or resize selected opening. Validate revision, unit bounds, object clearance, wall hosts, overlap and room topology using the same plan/scene services as direct edits. Preview the diff in 2D and 3D. Ask for clarification if there are several targets or missing dimensions. Require explicit apply for structural changes and a fresh architecture review after apply. Keep revision history, undo/restore and before/after design variants.
4. **Scene to media.** Start with PBR materials, lighting presets, a saved camera and deterministic image capture. Then use the existing RGB/depth/ID-mask path for optional local image generation. Add reference-image and selected-surface masking as measured improvements. Store model, prompt, seed, camera and plan/scene hashes with each output. Compare stylized results against the geometry preview at doors, windows and room boundaries. Add a deterministic camera-path video with the same scene and materials, then explore generative video separately with temporal consistency checks.

## Delivery sequence and proposed gates

All timing is a target to validate on the user's Mac. Record upload-to-draft, time spent reviewing, reviewed-to-walkable, time to first styled image and total operator time separately. Track cold and warm runs, model load, peak memory and swap, failures, manual interventions and cash cost per accepted deliverable. Keep failed and unsupported inputs visible by cohort.

| Work package | Deliverable and evidence | Dependency |
| --- | --- | --- |
| 1. Establish the baseline | Build a repeatable timestamped upload → draft → calibrated scene → preview benchmark using synthetic plans. For real accuracy use the production plan's 30 consented plans, 10 development and 20 locked held out. Annotate walls, room geometry, scale, openings and fixtures. Compare raster and vector paths before changing the default. Report misses and repair time. | POC A/B |
| 2. Fast editable walkthrough | On clean, single-floor inputs, target first editable draft P50 ≤60 s and P90 ≤120 s. After scale confirmation, make the same draft walkable and give it a default material preset. Use the existing Gate B tolerances and its five-minute correction budget before calling it trusted. Test passages through doors, blocked walls, window placement, keyboard and touch navigation, and at least 30 fps on the tested phone after load. | POC B/C/D |
| 3. Furnish and redesign | Curated metric assets, manual edit parity on desktop/touch, then scoped prompts for furniture, finishes and a small set of architectural edits. Test explicit targets, ambiguous targets, unit conversions, impossible changes, stale revisions and recovery. Require no unapproved structural edits, no opening displacement for styling-only changes and exact undo of commands in the test suite. | POC C/D |
| 4. Render and export | Verify real local image generation from the existing form on the M5. Target first deterministic styled view in ≤5 s after the scene is loaded and first local AI preview P90 ≤180 s once weights are warm. Score at least 10 viewpoints × 3 styles under gate E. Export saved-geometry GLB, stills and a path video. Verify reload and matching camera/geometry across outputs. Record Mac power use and downloads separately from recurring API cost. | POC C/E |
| 5. Extend to whole homes | Add selected PDF pages, floor/elevation alignment, level and stair connections, roofs/site imports, and GLB import with scale, axes and semantic coverage checks. Keep unsupported CAD elements visibly opaque. Benchmark multi-floor separately with held-out stairs, voids and differing floorplate outlines. Consider native CAD adapters only when real inputs justify their complexity and licensing cost. | After single-floor gates |
| 6. Share and extend devices | Package a slim read-only walkthrough. Add secure revocable external sharing after gate F, then evaluate WebXR, native headset and on-site AR against device requirements and tracking accuracy. Measure transfer size, time to interactive, FPS and memory on actual devices. | POC D/F |

**First implementation PR:** instrument the existing real local integration fixture for timed stages and add a benchmark report broken down by source format. Use the same run to identify where the first-minute budget is spent. Follow with a collision-aware single-floor walking mode based on the same calibrated geometry. These steps use synthetic data and need no Enviz purchase, provider credits or user input. Representative drawings with permission to use them and an actual M5 run are needed for the real-plan and hardware gates.

**Optional direct comparison:** if an Enviz project is already available, compare the same approved plan on both products. Record the initial deliverable, corrections and wait, rerun a selected object or opening edit, and compare model geometry, camera, GLB download and image output. Keep a versioned rubric and compare equivalent deliverables before making any claims about cost, turnaround or parity.

The synthetic demo reports upload, extraction, upload-to-draft and calibration times in milliseconds for PNG, JPEG and PDF. Run `npm run test:integration` from `apps/web` for the production browser capture and export timing in `test-results/**/workspace.json`. Each format has one sample per run.

With a calibrated plan, place and aim a camera, then focus the 3D view. WASD walks and arrow keys turn or move. Movement checks the path against wall chunks from floor to head height, closed doors and furniture. Save the scene to retain the viewpoint.

Use **Floor finish** in the 3D scene for an immediate whole-floor color and roughness preview. Save the scene to keep the finish. Camera capture and export include it without invoking an image provider.
