From model boxes
to verified architecture.

This is the target architecture for Florp, informed by the supplied Cortex Workshop Overview and lessons from the existing Florp prototype. It distinguishes implemented today from proposed engineering work, prioritizes free/local tooling, and does not imply that wall accuracy has been proven.

1 · Executive architecture decisions

One truthCanonical graph of shared wall nodes/edges, openings, room faces, source evidence and review state. No independent 2D and 3D wall copies.
Models proposeYOLO, vector extraction, OCR and multimodal vision yield evidence. Deterministic topology and constraints decide whether geometry is coherent.
Approval is explicitStructure approval and physical dimension approval are separate. Neither a detector confidence score nor an LLM claim is a user confirmation.
Single modular backendKeep FastAPI and SQLite/local disk; add clear modules and contracts. Do not introduce microservices, Temporal or MicroVMs for a one-person POC.
Replayable workImmutable uploads, extraction runs, model/config hashes, versioned proposed layouts and correction deltas.
Measure before trainingBenchmark current pretrained detectors on unseen scans; train only if recall/precision or correction time improves in controlled evaluation.

2 · Canonical execution pipeline

Original PDF / image→Classify source→Evidence bundles→Model proposals→Spatial graph solver→Human review→Verified scene→Controlled render

Ingestion and preprocessing

Now: PyMuPDF first-page raster, OpenCV line candidates, Tesseract OCR, persisted local previews. Next: per-page classification (vector / scanned / hybrid), coordinate transform records, multiple scan resolutions, orientation/deskew, PDF vector layer semantics and bounded image crops.

Evidence not predictions

Store every word, vector stroke, bounding box, mask or dimension chain with source_page, original coordinates, transform, crop ID, model name/version, confidence where available, and evidence references. Never conflate OCR's recognized text with proof of a dimension association.

AI provider adapters

Local pretrained YOLOv8 provides object bounding boxes; OpenCV offers weak line candidates; a configured vision LLM provides optional semantic hypotheses. Keep provider-specific schemas and credentials in backend. Validate complete JSON, handle truncated output, and prefer small focused crops to oversized free-form output. No AI service is required merely to inspect local evidence.

3 · Canonical connected spatial graph

Current Florp: independent room polygons, wall endpoints and opening records, with a read-only topology diagnostic endpoint. Target: one spatial graph; all UI and 3D views derive from the same immutable graph version.

EntityFields and invariant
NodeStable ID, blueprint-space XY, provenance, confidence and approval state; a junction is shared rather than duplicated
WallEdgestart_node_id, end_node_id, physical thickness/material if supported, opening references, source mask/box references
Openingwall_edge_id, parametric offset and width, height/sill, door/window type, inferred/confirmed evidence status
RoomFaceClosed boundary half-edges, adjacency and floor outline; never generated from an open contour
DimensionConstraintLabel, units, measurement type, anchor pair, source and confidence; global solve reconciles contradictions
Proposal / ReviewModel/version/config/evidence IDs, accept/move/reject/split/merge operations, reviewer and timestamps

Solver stages

1) Extract wall centerline/mask candidates. 2) De-duplicate collinear overlap. 3) Cluster endpoints and infer plausible T/corner intersections within tolerance. 4) Preserve alternative interpretations until review. 5) Anchor opening candidates to specific edges. 6) Polygonize topologically closed faces. 7) Run geometric/metric constraints and explain unresolved conflicts. None of these stages should overwrite human-confirmed coordinates without consent.

}

Validation layers

Structural: no missing edge references, invalid length, impossible face winding or overlapping edge duplicates; report dangling endpoints and ambiguous intersections. Metric: verified scale, dimension agreement, opening extents and correct wall heights. Render: required walls/windows/camera do not move across design revisions.

4 · Automatic measurement recovery

Product rule: users should not normally type px_per_meter. It is an internal coordinate transform, not a primary UX control. A scan may not contain sufficient unambiguous units; the engine must abstain rather than invent a scale.

OCR / PDF text+Dimension arrows / lines→Anchor matching→Constraint graph→Robust scale solve→Confirm exceptions

Recognize numeric text, unit conventions, chains, witness/extension lines, rotation and parent geometry; solve multiple consistent dimensions using robust loss and flag outliers. A label such as “500” next to furniture is not automatically 5 metres. If only one credible dimension exists, show the image crop and ask a single grounded confirmation.

Opening sill/height and concrete-vs-partition classification often require elevations, schedules or legend conventions; mark unknown rather than infer unsupported exact values.

5 · Mobile-friendly correction and training loop

Primary UX is “Here is the reconstructed plan; check these three uncertain areas” instead of tracing every wall. Use one-tap accept/reject of highlighted source-backed candidates, junction drag handles, small crop comparisons, undo/redo and revision history. For a correction, record model prediction, original coordinates, corrected geometry, source image region and model version. Keep private user plans and labels off public Git.

Trainable labels must include positive walls, false walls, missed walls, door/window openings, and junction corrections; negative-only sessions cannot establish detector recall. Evaluate by project-level split, not image crops from the same floor plan across train/test.

6 · Durable, replayable processing

Borrow Cortex's durable-work semantics, not its production infrastructure footprint. A local SQLite table and lightweight worker are sufficient for the POC. One job can be safely retried using an idempotency key derived from upload hash + model/config version + requested action. Persist status, attempts, error category, output artifact paths, costs and durations. Store events and immutable layout versions so failed stages resume without repeating paid AI calls.

7 · Verified geometry → 3D → controlled images

Reconstruct wall solids, explicit opening voids, floors and ceilings in Three.js / React Three Fiber from one approved graph version. Associate camera IDs and transforms with that version. Capture depth, edge, normals and ID/segmentation masks where supported; these are visual conditioning signals, not fidelity guarantees. Generate through one real configured provider; record model, seed, prompt, mask and control artifacts. Validate output against source geometry before exposing it as “geometry faithful”. Preserve geometry/camera when editing material, color, furniture or lighting.

Do not claim render functionality is complete: Florp currently has a white-box viewer and an incomplete image-generation adapter. Real conditioned generation and automated structural QA remain future work.

Planning target, not measured performance: at least 90% of supported plans reaching acceptable structure within five minutes of human correction. Track before/after intervention separately. A trained model is not automatically the answer: often topology constraints improve output more than switching detectors.
