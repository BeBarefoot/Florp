FLORP / DEVELOPMENT GUIDE

Validate first. Train only if needed.

Practical sequence for improving the floor-plan extractor on macOS. This is a procedure, not a claim that production accuracy has been achieved.

1 · Establish the current state

Florp already uses pretrained Yytsi wall segmentation and object detection, provides draft editing, connected-geometry repair and a 3D preview. The supplied corrected plan still has 30 disconnected wall groups, 64 loose endpoints, no supported closed room faces and one provisional opening without confirmed scale. These counts do not measure precision or recall.

The original input raster and independently reviewed reference were not supplied for a fresh benchmark. The Mac parser is not integrated or tested yet.

2 · Assemble an evaluation set

  1. Collect representative original PNGs or PDF-rendered rasters, including scans, Hebrew/English labels and varied wall/opening styles. Confirm usage rights.
  2. Record exact image dimensions, SHA-256 and building/project group. Assign entire groups to development, validation or locked test; keep related floors, versions and crops together.
  3. Start with a small development set and reserve at least 10 independent buildings for the minimum held-out gate. More are needed to represent real customers.
  4. Independently annotate every actual wall axis, room boundary and opening span/host. Capture scale where independently verified. A second reviewer checks the whole drawing and missed regions.

Saved corrections and detector decisions are starting evidence, not automatically complete ground truth. Never use the same test examples for tuning or training.

3 · Compare existing models without training

  1. Freeze the source images, reference, software versions, settings and checkpoint hashes.
  2. Run current Florp and, after a Mac compatibility and licensing spike, the proposed parser on the identical raster. Save raw outputs before correction.
  3. Normalize predictions to the exact source coordinate frame and image hash. A parser-specific importer still needs to be built.
  4. Calculate wall-length precision/recall, junction and adjacency F1, room overlap, opening span and host accuracy; track scale error, correction time, runtime, peak memory and failures.
  5. Inspect overlays and categorize failures. Tune only on the development/validation split; rerun the locked test only for a frozen release candidate.

The parser uses Raster2Seq; its default published checkpoint is CC BY-NC 4.0. Source and model licenses differ. Verify rights before commercial use; CPU fallback is not a verified Mac result.

4 · Improve the engine before training

For each error ask whether the model missed pixels, the coordinate conversion shifted them, or graph reconstruction made the wrong decision. Fix and test transforms, wall junctions, host associations and scale separately. Keep every proposal reversible and never overwrite corrected geometry.

FailureFirst action
Shifted masks or windowsVerify resize, padding and image-coordinate transforms.
Disconnected wallsInspect junction splitting and evidence-supported gap proposals.
Wrong window span or hostReview full endpoints and host mapping; leave ambiguity unresolved.
Missing wall pixels across many stylesCompare pretrained candidates; consider training if failures persist.

5 · Train only when evidence supports it

  1. Acquire licensed training images and annotate complete wall, door and window pixel polygons; wall centerlines alone do not define accurate masks.
  2. Have an independent reviewer verify all annotations; group by building and keep test groups locked. Prepare immutable, hashed datasets with the existing validation tool.
  3. Use a trusted local segmentation checkpoint and verify code, model and dataset licensing. Begin with a small smoke test, then train candidate runs and tune on validation only.
  4. Record the exact checkpoint and data hashes, settings, seed, device, software versions, training metrics, failures and output weights. Run multiple seeds when comparing candidates.
  5. Freeze the candidate and run held-out segmentation and end-to-end geometry evaluation. Measure against the original baseline, not the corrected output.

Runnable schemas and commands are in PRODUCTION_2D_PROCEDURE.md. Training on a Mac can be slow or exceed memory; check the device and batch size with a smoke run.

6 · Release decision

The current automated minimum geometry gate requires at least 10 independent test buildings; per-plan wall-length precision and recall ≥90% at 3 source pixels; junction and wall-adjacency F1 ≥95%; room-region F1 ≥90%; opening-span precision and recall ≥95%; checked exterior completeness; and at least 80% corrected within five minutes. This is a proposed policy, not demonstrated accuracy.

Also evaluate window-host identity, scale, per-room accuracy, latency, memory and failure rates. These are not all automated. Public deployment additionally requires authorization, isolation, resilient jobs, monitoring, backups and operational testing. Passing the geometry gate alone is not production approval.
