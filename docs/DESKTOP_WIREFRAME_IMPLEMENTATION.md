# Florp desktop implementation plan

Design input: Flor Web Wireframe Cards v2, W01–W20. Code baseline: `510281d`. This is a proposed delivery plan. The first release is complete when a buyer can correct an imperfect extraction, calibrate or continue approximately, enter the same space, edit furniture directly, and reopen the saved result. A synthetic perfect plan alone cannot establish that outcome.

## Architecture and ownership

| Existing owner | Responsibility in the desktop implementation |

## First release — implement in this order

Each row is a separately testable change. Start from an existing uploaded plan so recognition and editing can be validated before redesigning the landing page.

| Step and cards | Implementation against existing code | Acceptance before moving on |
|---|---|---|
| **1. Record the baseline and establish the workspace shell** · W04–W08 | Capture the yard and blurry-apartment flows on the baseline. In TopBar and Showcase expose **Plan · Overview · Walk**. Keep split comparison inside Plan. Carry blueprint, floor and active selection across mode changes. Retain the camera when returning from an object edit. Use the existing phone routes and gesture handlers. | Starting from a direct plan URL, change modes, open and dismiss a tray, and return to the same floor. Keyboard focus returns to the invoking control. An unsaved plan edit survives the switch or the user can explicitly save or discard it. The current phone tour still opens directly. |
| **2. Review one uncertain finding** · W04 | Use existing opening evidence, wall-closure suggestions and [editing operations](../apps/web/lib/plan/ops.ts). Derive a review list from the current revision. Frame the same span in the source crop and model preview using drawing coordinates. Start with one ambiguous doorway. Extend to closures and uncertain fixtures after the first path works. Offer Door, Open passage, Solid wall and Skip where the geometry supports each choice. Add an entry to mark a missing feature directly on the source when the detector produced no candidate. | On the yard, locate a top-wall opening against the scan, correct it, undo, reapply and reload. Verify host wall, span and adjacent windows. On the apartment, skip a faint symbol and individually accept another. A skipped suggestion stays unresolved. A tentative fixture stays a preview until accepted. New plan revisions invalidate stale review actions. |
| **3. Calibrate or continue approximately** · W05 | Present endpoints from the [scale proposal](../apps/api/app/plan_scale_proposal.py) on the drawing. Show the entered or recognized length with units. Overlay an independent second reference and display its observed discrepancy. Use the existing manual calibration path when OCR is unavailable or evidence conflicts. Route approximate users into the preview capabilities already supported. | Exercise matching references, inconsistent axes, absent OCR and a user choosing approximate mode. On reopening, distinguish a saved calibration from an estimate. Do not show metric fit guarantees or a verification badge based on one printed value. |
| **4. Walk, select and furnish** · W06, W08, W11 | Place the catalog in a horizontal floating tray. Keep Overview reachable while walking. Use [object menu](../apps/web/components/plan/WalkthroughEditMenu.tsx) and FurniturePlacement for hover, click, drag, size, rotate and replace. Give camera, object drag and tray scrolling distinct pointer handling. Keep a missing-room fallback as an optional repair. Use [fit checks](../apps/web/lib/plan/furnitureFit.ts) to highlight the actual door arc or overlapping footprint. A proposed nudge must be recomputed and validated before application. | Enter the yard kitchen, drag the detected dining set, resize, rotate, replace and save it. Verify model dimensions, orientation and position after reload. Repeat on incomplete flooring. Walk afterwards, zoom Overview toward the pointer, and drag a view pin onto the yard. Ensure a second touch still controls the camera. Approximate-mode edits expose their actual persistence status. |
| **5. Restyle the space and save it** · W07, W09, W12 | Offer the six [existing styles](../apps/web/lib/plan/homePresets.ts) on the buyer's current view. Use [wall faces](../apps/web/lib/plan/wallFaces.ts) for the complete selected side and [finish controls](../apps/web/components/plan/FinishSheet.tsx) for material, color and dimensions. Present scope at the point of application. Preview, apply and revert. Show saving, saved, failed and revision-conflict states from real writes. | Apply a whole-floor style while preserving an explicit bathroom override, then change one wall face and verify its opposite side. Reopen with the same scene and saved camera. From a second tab force a revision conflict and retain the pending edit for recovery. |
| **6. Connect the front door** · W01–W03 | Add first-visit upload/sample and returning-user Continue to the home route. Reuse the project upload path. Preview orientation and PDF page-one behavior. If rotation is offered, apply one consistent transform to source, extraction and overlays. Reuse [backend progress polling](../apps/web/lib/plan/extractionProgress.ts) and its actual stage/percentage. Handle upload failure separately from extraction failure. | From a fresh session upload a supported file, reach review, and reopen it from Recent homes. A failed retry does not duplicate the project/floor. Simulate a dropped progress poll, invalid file and failed extraction. Only offer cancellation or resumability for operations that implement it end to end. |

### Desktop interaction and visual treatment

Use the proposed cream work surface, forest primary action and terracotta attention accent. Apply tokens in [desktop styles](../apps/web/app/globals.css) under the desktop workspace scope. Keep the existing Florp display name pending a branding decision. Repair malformed standalone SVG cards W01–W04, W08, W09, W13 and W19 if they are used as design assets. Build production controls from the app's components.

For precision work, the source and model should share a selected span, with independently adjustable zoom available after initial framing. For discovery, maximize the canvas. Keep a compact object menu near the projected selection, clamp it inside the viewport and dismiss it on Escape or an outside click. A furniture card needs its name and dimensions. A permanent instruction paragraph consumes space needed for placement. Use tooltips, keyboard labels and visible focus for icon actions. On a small laptop allow the tray to scroll horizontally while its close action stays reachable. Keep scroll over the tray from changing the camera.

## Verification and release sequence

1. **Record the starting point.** Use the yard, blurry apartment, second floor and farmhouse wherever source and independent annotations are available locally. Record revision, fixture availability, wall/opening matches, room boundaries, reviewed object classes and scale reference error. Track missing labels or unavailable fixtures explicitly. Compare automatic extraction separately from the buyer-corrected model. Keep scans and debug bundles outside Git. Use the [benchmark contract](EXTRACTION_BENCHMARK.md).
2. **Automate the critical journey.** Extend [review workflow](../apps/web/tests/review-workflow.spec.ts), [plan editor](../apps/web/tests/plan-editor.spec.ts), [showcase](../apps/web/tests/showcase.spec.ts) and [upload](../apps/web/tests/upload.spec.ts) with synthetic or approved fixtures. Assert persisted IDs, dimensions, positions, revisions and camera pose, alongside visible controls. Cover empty, approximate, calibrated, stale and failed-save states.
3. **Check the shared implementation.** Run focused tests for each change. Run the production web build, backend, local integration and browser workflow before release. Recheck mouse, keyboard, trackpad and Android two-finger gestures because desktop and phone share the renderer. For persistence changes exercise older scene records, interrupted writes and retries. Use [scene API tests](../apps/api/tests/test_scene_api.py) for revision handling.
4. **Review with a buyer.** Start on the yard, repair an opening, check scale, furnish, switch to Walk and reopen on the phone. Repeat with the blurry apartment, deliberately skipping a finding. Record completion, time, wrong selections, missed changes and each place they ask for help. Set speed and accuracy targets after collecting baseline evidence. The first release can ship independently of offline caching, designer proposals and multi-floor traversal.

## Decisions and first work item

Proceed with Florp as the working name, local single-user storage, explicit saves for durable edits and the existing catalogue. Public sharing, paid rendering, automatic structural classifications and a brand rename require separate product decisions before exposing those experiences. The first implementation ticket is **W04: review one ambiguous opening on the yard plan**. Deliver the paired source/model selection, correct/skip/undo actions and reload test in the existing editor. Use that working interaction to refine the desktop shell before broad styling work.
